Chapter 01

Project Overview, Core Philosophy & Business Economics

1.1 Edito Kya Hai? (In Simple Words)

Edito ek modern, commercial-grade, browser-native Music Production & Creative Multimedia Studio hai. Yeh user ko 11 dedicated audio processing tools, 8 creative photo/video tools, aur ek complete Moises-style 4-Track Digital Audio Workstation (DAW) provide karta hai — aur sabse badi baat: bina kisi cloud upload ya subscription ke!

Traditional platforms jaise Moises.ai, Adobe Podcast, ya Canva user ki media files ko apne cloud servers (AWS EC2 / S3) par upload karwati hain, jisse:

  • Heavy Server Cost: Har audio/video processing ke liye powerful GPU instances ka bill company ko pay karna padta hai ($0.05 se $0.20 per song).
  • Privacy Risk: User ka personal song, voice recording, ya private video company ke third-party cloud par store hota hai.
  • Queue & Slow Speed: File upload hone me time lagta hai, cloud render queue me wait karna padta hai, aur download limit aati hai.
💡 Edito Ka Architectural Breakthrough: 100% In-Browser DSP
Edito me 0 bytes media file server par upload hoti hai! User ke computer ka apna CPU, GPU (WebGPU / WebGL) aur RAM use karke browser ke andar Web Audio API, WebAssembly (WASM) aur Canvas 2D ki madad se real-time signal processing hoti hai.

1.2 Business & Economic Model ($0 Cloud Compute Model)

Agar traditional SaaS me 1,00,000 active users roz 5 audio/video process karein, toh server infrastructure ka monthly kharcha ₹15,00,000 se ₹40,00,000 ho sakta hai. Edito ka architectural model is compute cost ko bilkul 0 kar deta hai.

Traditional Cloud SaaS (Moises / CloudConvert)

• User uploads 100MB video to Cloud Server.
• Cloud server runs FFmpeg / Python script.
• High bandwidth cost + High CPU/GPU bill.
• Limited free tier (e.g. 5 mins only).

Edito Client-Side Model

• File stays strictly in browser RAM.
• Client device processes samples via WebAudio & WASM.
• Zero compute cost for founder/owner.
• 100% free, unlimited, and lightning fast.

2.2 In-Browser Audio Processing Lifecycle (Memory & ArrayBuffers)

Jab user koi audio ya video file drag-and-drop karta hai, toh background me step-by-step kya hota hai:

  1. File Reading: Browser ki HTML5 File API se file.arrayBuffer() read hota hai (raw bytes in memory).
  2. Decoding: AudioContext.decodeAudioData(arrayBuffer) raw compressed container (MP4, MP3, AAC, OGG) ko decompress karke AudioBuffer me convert karta hai.
  3. PCM Float32 Representation: AudioBuffer me audio samples -1.0 se +1.0 ke floating-point numbers me convert hote hain (e.g. 44,100 samples per second per channel).
  4. Digital Signal Processing (DSP): Cutter slice karta hai array indices ko, Speed resample karta hai linear interpolation se, Volume multiplier lagata hai Float32 arrays par, aur Vocal Remover phase cancellation (L - R) karta hai.
  5. Encoding: Processed Float32 PCM ko 16-bit Int16 me quantize karke @breezystack/lamejs MP3 bitstream ya standard WAV file me pack karta hai.
  6. Direct Download: URL.createObjectURL(blob) se file seedhe user ke local computer par download ho jati hai. Processing khatam hone par memory release (GC) kar di jaati hai.

Chapter 05

Core 11 Audio Tools: Deep Technical Breakdown & DSP Math

Har tool ke andar digital signal processing ka exact mathematical aur algorithmic logic yaha detail kiya gaya hai:

1. AI Stem Separator (/stems)

Working Principle: Full mixed song ko 4 individual audio stems (Vocals, Drums, Bass, Other) me split karta hai. Background me stems.worker.ts Web Worker ONNX Runtime Web aur WebGPU ke through deep learning spectrogram separation model execute karta hai. Output ko 4 Float32 AudioBuffers me convert karke multitrack mixer me feed kiya jata hai.

2. AI Vocal Remover & Karaoke (/audio/vocal-remover)

Working Principle (Center Channel Cancellation): Commercial stereo music tracks me lead vocals ko mixing engineer center channel (Mono) me balance karta hai, jabki instruments (Guitars, Synths, Reverbs) Left aur Right channels me panned hote hain.
Formula: Karaoke_Sample[i] = (Left_Channel[i] - Right_Channel[i]) * 0.707
Is phase cancellation se vocals cancel out ho jaate hain aur clean instrumental background track bachta hai.

3. Video to Audio Converter (/audio/video-to-audio)

Working Principle: User ke MP4, WebM ya MKV video file ko browser ki memory me decodeAudioFromFile() read karta hai. Browser ka native multimedia decoder video frames ko drop karke sirf audio container streams ko demux karta hai aur raw PCM samples extract karta hai. Uske baad audioBufferToMp3() 128k/320k bitstream encode karke genuine MP3 file download karwata hai.

4. Waveform Audio Cutter & Trimmer (/audio/cutter)

Working Principle: User canvas par start time (T1) aur end time (T2) select karta hai.
Sample Index Calculation: Index_Start = Math.floor(T1 * sampleRate), Index_End = Math.floor(T2 * sampleRate).
sliceAudioBuffer() exact sample index par new AudioBuffer allocate karta hai aur subarray() copy karta hai. Zero audio quality loss!

5. Audio Bitrate Compressor (/audio/compress)

Working Principle: Heavy 50MB WAV ya 320kbps audio ko 64kbps, 96kbps ya 128kbps me re-quantize karta hai. LAME psychoacoustic model un frequencies ko filter out karta hai jo human ear clearly detect nahi kar sakti, jisse audio file size 80% tak reduce ho jaata hai bina noticeable audio degradation ke.

6. Tempo & Pitch Shifter (/audio/speed)

Working Principle: changeBufferSpeed() linear interpolation resampling use karta hai. Agar speed 1.5x karni hai, toh new buffer length originalLength / 1.5 hoti hai. New sample values adjacent original samples ke weighted average se compute ki jaati hain: sample = s1 + (s2 - s1) * fraction.

7. Audio Merger / Concatenator (/audio/merger)

Working Principle: Multiple audio tracks ko sequentially join karta hai. Total sample length calculate hoti hai (Length_Total = Length_1 + Length_2 + ...). New master buffer create hota hai aur set() method se sub-arrays ko sequentially memory offset me append kiya jata hai.

8. Audio Splitter (/audio/split)

Working Principle: Ek lambe audio track (e.g. 1 ghante ka podcast) ko equal time chunks (e.g. 5-5 minutes) ya user-defined cue markers par divide karta hai aur automatically numbered separate files export karta hai.

9. Volume Booster & Normalizer (/audio/volume)

Working Principle: Low volume recordings ko 200% tak boost karta hai. Peak detector poore buffer me maximum amplitude find karta hai. Peak normalization algorithm gain apply karta hai: Sample[i] = Math.min(1.0, Math.max(-1.0, Sample[i] * Gain)), preventing digital clipping and distortion.

10. Audio Converter & 11. Blank Generator

Audio Converter (/audio/converter): Seamless format switching between WAV, MP3, AAC container blobs directly in memory.
Blank Audio Generator (/audio/blank-audio): Exact specified duration (e.g. 30.5 seconds) ka zero-amplitude PCM buffer allocate karke silence track create karta hai video editing timeline sync ke liye.

Core 8 Creative Photo & Video Tools: Deep Technical Breakdown

Creative photo aur video tools ka rendering engine HTML5 Canvas 2D, TypedArrays (Uint8ClampedArray), aur Web Media APIs par based hai:

1. Video Clip Trimmer & Speed Editor (/creative/video-editor)

Architecture: Browser-side video trimming bina cloud FFmpeg ke. User input video ko HTML5 <video> element me bind kiya jata hai. Jab user "Render Trim" click karta hai, video trimStart par seek hota hai. Video element se video.captureStream() grab kiya jaata hai aur MediaRecorder chunks collect karta hai jab tak trimEnd nahi pahuchta. Speed rate (0.5x, 1x, 2x) aur mute toggle dynamically stream track me synchronize hote hain.

2. Watermark Remover & Inpainter (/creative/remove-watermark)

Architecture (Image Inpainting): User canvas par watermark ke upar mask brush draw karta hai. Algorithm ctx.getImageData() se pixel RGBA array analyze karta hai. Masked region ke boundary pixels ke color gradients aur textures ko iterative radial blur aur weighted diffusion ke through mask area me fill kiya jaata hai, jisse watermark background me blend ho jata hai.

3. Background Cutout (/creative/remove-background)

Architecture: Color distance metric aur alpha thresholding. Corner pixels ka sample lekar background color estimate hota hai. Har pixel ka Euclidean distance calculate hota hai: Distance = Math.sqrt((R1-R2)^2 + (G1-G2)^2 + (B1-B2)^2). Agar distance threshold se kam hai, toh Alpha channel ko 0 (transparent) set kar diya jata hai.

4. Bulk Image Resizer (/creative/resize-image)

Architecture: High-quality bicubic resampling. Canvas 2D image scaling step-down technique use karta hai taaki high-res images ko shrink karte waqt pixel moire patterns ya blurriness na aaye. Aspect ratio locking aur batch ZIP export support karta hai.

5. Photo Canvas Editor (/creative/photo-editor)

Architecture: Interactive affine transformation matrix. User crop, 90-degree clockwise/counter-clockwise rotation, horizontal/vertical flip, freehand drawing brush, aur text overlay kar sakta hai. Canvas coordinates mouse position se calculate hote hain.

6. Photo Collage Maker (/creative/make-collage)

Architecture: Dynamic grid layout generator (2x2, 3x3, polaroid, unequal mosaic). Har uploaded image canvas cell ke dimension me aspect-fit ya aspect-fill hoti hai, customizable outer border padding aur corner radius ke sath.

7. Aesthetic Photo Filters & 8. Face Retouch

Aesthetic Filters (/creative/apply-effects): Direct pixel RGBA matrix manipulations: Vintage (Sepia matrix), Cyberpunk (high contrast magenta/cyan split), Noir (monochrome weighted luminance: 0.299R + 0.587G + 0.114B).
Face Retouch (/creative/retouch): Surface blur and bilateral filter approximation jo skin texture ko smooth karta hai jabki high-frequency edges (eyes, lips) ko sharp rakhta hai.

const startTime = audioContext.currentTime + 0.05; // 50ms scheduling buffer
sourceNodes.forEach(source => source.start(startTime, currentOffset));

Real Problems Faced & Exact Solutions Implemented

Yeh section is project ke development ke dauran aayi 10 real-world technical problems aur unke exact solution ko explain karta hai. Interview me yeh batane se interviewer 100% impress hota hai:

BUG #1 Video-to-Audio conversion me file convert ho rahi thi par sound bilkul nahi aa raha tha (Silent Audio Bug).
Root Cause: Code me do badi galtiyan thi:
1. AudioToolbox.tsx me audio export karte waqt line 223 par ctx.createBuffer(2, 44100 * len, 44100) likha tha, jo memory me ek empty, silent buffer create kar raha tha jisme saare samples 0.0 the. Decoded video ka real audio buffer usme copy hi nahi ho raha tha.
2. creative/video-to-audio/page.tsx me raw WAV byte headers export ho rahe the lekin extension .mp3 diya gaya tha, jisse media players format mismatch ki wajah se audio decode nahi kar paa rahe the.
Exact Solution: Humne project me @breezystack/lamejs install kiya. audioContext.ts me decodeAudioFromFile() function likha jo video file se audio stream ko safely decode karta hai, aur audioBufferToMp3() banaya jo Float32 samples ko Int16 me scale karke genuine MP3 bitstream banata hai. Saath hi video-to-audio page me real-time HTML5 audio preview player add kiya taaki user download karne se pehle sound sun sake.
BUG #2 Admin Dashboard me fake mock data (1,435 visitors, 724 operations) aur hardcoded admin credentials aa rahe the.
Root Cause: Prototype stage me banaye gaye static UI mocks aur sample charts default state me render ho rahe the jab MongoDB database empty tha.
Exact Solution: Strict Zero-Mock Data Policy enforce ki gayi. Backend aur Frontend dono me saare telemetry metrics aur charts ko genuine state par map kiya. Agar database me zero events hain, toh dashboard strictly 0 display karega. Admin login page se hardcoded email/password attributes ko completely remove kiya gaya.
BUG #3 Next.js build (`npm run build`) fail ho raha tha: "Event handlers cannot be passed to Client Component props".
Root Cause: src/app/privacy/page.tsx ek React Server Component (RSC) tha, lekin uske andar ek "Back to Top" button par onClick handler laga hua tha. Next.js 15 App Router me Server Components me interactive client event handlers allowed nahi hote.
Exact Solution: Humne routing ko decouple kiya: static SEO metadata ke liye src/app/privacy/layout.tsx (Server Component) banaya, aur page file src/app/privacy/page.tsx ke top par "use client"; directive lagakar usko Client Component me convert kiya. Iske baad build 100% exit code 0 ke sath pass ho gaya.
BUG #4 Client-side video trimming bina cloud FFmpeg server ke kaise achieve karein?
Root Cause: Traditional video editors cloud EC2 server par FFmpeg run karte hain jo costly hota hai. Browser me full FFmpeg WASM run karne ke liye COOP/COEP HTTP headers aur 30MB initial bundle download karna padta hai jo slow connection par fail ho jata hai.
Exact Solution: Humne HTML5 Video element aur browser ke native MediaRecorder stream capture API ka use kiya. Video user ke select kiye gaye trimStart par seek hoti hai, video.captureStream() se real-time video frames capture hote hain, aur trimEnd aane par stream stop hokar instant trimmed MP4/WebM blob export hota hai. Zero cloud cost, 100% privacy!
BUG #5 Audio Compressor tool me browser sirf WAV export kar raha tha, jisse compressed file ulta badi ho rahi thi!
Root Cause: Web Audio API natively sirf uncompressed 32-bit linear PCM (WAV) support karta hai. Agar user 5MB ki MP3 file compress karne ke liye upload kare, toh standard browser WAV export usko 40MB ka bana deta tha.
Exact Solution: Humne pure JavaScript/WASM LAME MP3 encoder (@breezystack/lamejs) integrate kiya. User jab 64kbps, 128kbps ya 192kbps select karta hai, encoder frames ko re-quantize karke actual MP3 frames emit karta hai, jisse file size 80% tak chhota ho jata hai.
BUG #6 Audio Speed change karne par chipmunk effect (pitch badal jana).
Root Cause: Simple sample decimation ya naive resampling time aur frequency dono ko affect karti hai.
Exact Solution: Humne speed change ke liye linear interpolation resampling implement kiya, aur independent pitch shifting ke liye pitchShift.ts me Phase Vocoder Short-Time Fourier Transform (STFT) implement kiya jo magnitude aur phase angles ko separate karke bina tempo badle pitch ko modify karta hai.
BUG #7 Browser tab me Next.js default branding ("What would you like to create?" and 'N' icon) show ho raha tha.
Root Cause: Default Next.js starter templates me metadata aur favicon dynamic handlers preconfigured nahi the.
Exact Solution: Humne dynamic route handlers src/app/icon.tsx aur src/app/apple-icon.tsx create kiye, high-resolution vector src/app/icon.svg add kiya, multi-resolution favicon.ico generate kiya, aur root layout.tsx me clean title template set kiya: Edito | %s with default Edito — Free In-Browser Music & Creative Studio.
BUG #8 Large media files (100MB+ audio ya 4K photos) process karte waqt browser tab crash (Out of Memory - OOM) ho sakta hai.
Root Cause: V8 engine me JavaScript heap limit typically 2GB se 4GB hoti hai. Agar har step par new Float32 array copy banegi, toh memory spike hone par browser tab crash ho jaega.
Exact Solution: Humne 3 memory optimization techniques lagayi:
1. Memory Subarray Views: New buffer allocate karne ke bajay subarray() views use kiye jo existing memory pointer ko refer karte hain.
2. URL Cleanup: File download hote hi URL.revokeObjectURL(url) call karke blob memory release karayi.
3. Canvas Dimension Clamping: 4K ya 8K images ko process karne se pehle maximum 4096px par clamp kiya taaki texture memory overflow na ho.
BUG #9 AI Stem Separation run karte waqt browser ka UI freeze / hang ho jaana.
Root Cause: Deep learning neural network matrix multiplications main JavaScript thread par chalne se browser render loop (60 FPS) block ho jata hai, jisse buttons aur animations freeze ho jaate the.
Exact Solution: AI model execution ko dedicated Web Worker (src/workers/stems.worker.ts) me offload kiya. Web Worker background thread me WebGPU/WASM ke zariye inference run karta hai aur main UI thread par sirf postMessage({ progress: 45 }) emit karta hai. Result: UI bilkul smooth aur responsive rehta hai.
BUG #10 Telemetry collect karni thi lekin Privacy Policy "100% Zero-Retention" bhi preserve karni thi.
Root Cause: Analytics ke liye data chahiye hota hai, lekin privacy law (GDPR/DPDP) aur user trust ke hisaab se IP ya personal media store karna illegal hai.
Exact Solution: Humne Zero-Knowledge Telemetry Pipeline banayi:
1. Client-side par IP ko daily-rotating secret salt ke sath SHA-256 hash kiya jata hai.
2. Kabhi bhi user ka uploaded audio/video file name, metadata, ya content payload me include nahi hota.
3. Backend par automated retention worker chalaya jo 90 din se purane records ko database se permanently wipe out kar deta hai.

Q2 Web Audio API kya hai aur yeh standard HTML5 `<audio>` tag se kaise alag hai?
Answer: Standard <audio> tag sirf sound play, pause, ya seek karne ke liye use hota hai (high-level media playback). Jabki Web Audio API ek complete, low-level Digital Signal Processing (DSP) system hai jo audio routing graph model follow karta hai. Isme hum audio samples ko raw PCM Float32 arrays ke roop me manipulate kar sakte hain, mathematical biquad filters laga sakte hain, phase cancel kar sakte hain, volume gain modulate kar sakte hain, aur dynamic frequency spectrums analyze kar sakte hain.
Q3 Video to Audio conversion bina backend server ya cloud FFmpeg ke browser me kaise possible hai?
Answer: Modern browsers me built-in hardware media decoders hote hain. Jab hum AudioContext.decodeAudioData() ko video file ka ArrayBuffer pass karte hain, toh browser internally container demuxing karta hai — video track ko discard kar deta hai aur audio track (AAC, MP3, Opus) ko decode karke uncompressed PCM AudioBuffer me return kar deta hai. Uske baad hum @breezystack/lamejs se us PCM data ko MP3 bitstream me encode karke user ko download karwa dete hain.
Q4 AudioBuffer ke andar data kaise represent hota hai? Float32Array aur Int16Array me kya difference hai?
Answer: Web Audio API me uncompressed audio Float32Array me hota hai, jaha har sound sample ek floating-point number hota hai between -1.0 and +1.0. Lekin standard 16-bit audio files (CD quality WAV / MP3) me samples 16-bit signed integers (Int16) hote hain (between -32768 and +32767). Export karte waqt hum quantization formula lagate hain: int16Sample = Math.max(-1, Math.min(1, floatSample)) * 0x7FFF.
Q5 Lamejs kyu install kiya? Browser natively MP3 export kyu nahi kar sakta?
Answer: Browser ka native MediaRecorder sirf WebM ya OGG audio export karta hai, aur standard Web Audio API sirf uncompressed WAV banata hai. Standard browsers me MP3 audio encoder ka direct API nahi hota licensing aur patent history ki wajah se. Isliye humne @breezystack/lamejs (jo LAME C-codebase ka pure JavaScript/WebAssembly port hai) use kiya taaki universal .mp3 format client RAM ke andar hi generate ho sake.
Q6 Agar user 500MB ki badi video ya 1 ghante ka audio upload kare, toh browser crash kyu nahi hota?
Answer: Humne 3 core strategies use ki hain:
1. Memory Subarray Views: Hum raw arrays ko duplicate copy karne ke bajay memory buffer ke direct TypedArray.subarray() pointers use karte hain.
2. Sequential Chunking: Large files ko chhote time segments me chunk karke process kiya jata hai.
3. Immediate URL Revocation: URL.revokeObjectURL(blobUrl) call karke browser garbage collector ko memory free karne ka signal diya jata hai.
Q7 Client-side Video Trimmer kaise kaam karta hai?
Answer: Hum HTML5 Video element se captureStream() capture karte hain. Video ko user ke trimStart par seek karte hain aur MediaRecorder ko start karte hain. Video realtime me trimEnd tak play hoti hai aur uske video/audio tracks record hote hain. Jaise hi trimEnd aata hai, recorder stop hota hai aur final trimmed MP4/WebM blob generate ho jata hai.
Q8 AI Stem Separation browser me run karne ka kya mechanism hai?
Answer: Hum Microsoft ka ONNX Runtime Web (onnxruntime-web) use karte hain. Model weights client ke browser cache me store hote hain. Execution Provider ke roop me WebGPU use hota hai (fallback to WebAssembly multi-threading). Audio ka Short-Time Fourier Transform (STFT) nikaal kar spectrogram neural net me pass hota hai jo 4 stems ke masks generate karta hai.
Q9 Web Workers kyu zaroori hain?
Answer: JavaScript single-threaded hai. Agar heavy calculations (AI inference, audio resampling, chord detection) main thread par run hongi, toh browser ka UI freeze ho jayega aur "Page Unresponsive" warning aayegi. Web Workers in tasks ko background OS threads par run karte hain, jisse UI 60 FPS par smooth chalta rehta hai.
Q10 LocalStorage ke bajay IndexedDB kyu use kiya?
Answer: LocalStorage synchronous hai aur uski storage limit sirf 5 Megabytes hai. Multitrack audio studio me ek song ke 4 stems 50MB se 100MB tak hote hain. IndexedDB asynchronous hai, structured binary blobs store kar sakti hai, aur disk capacity ke 50% tak (gigabytes) store kar sakti hai bina UI ko freeze kiye.
Q11 Watermark Remover ka algorithm kaise kaam karta hai?
Answer: Yeh Image Inpainting technique par based hai. User ke banaye gaye mask area ke boundary pixels se sample values li jaati hain. Boundary pixels ka weighted average aur radial blur calculate karke masked pixels ko iteratively replace kiya jata hai. Isse surrounding textures watermark region me seamlessly blend ho jaate hain.
